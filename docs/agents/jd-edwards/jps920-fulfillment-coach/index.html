What it demonstrates

How do my latest priority and stock-reserve rules change the backorder review?

  • Keeps technical connection settings out of the end-user conversation.
  • Learns priority, inactive-status, donor-reserve, and approval corrections incrementally.
  • Applies relevant feedback across sessions and explains how it affected the answer.
  • Maintains a read-only recommendation and explicit human-approval boundary.

Connection context

The builder fixes environment JPS920, role *ALL, and device paf-jde-agent in the REST source. End users are never asked for technical connection headers.

Agent Memory

Realistic one-at-a-time corrections are captured during normal work. A later analysis includes an Applied from your prior feedback audit section for relevant recalled rules.

Prerequisites

  • Private Agent Factory 26.7-compatible environment with Agent Memory and cross-thread sharing enabled.
  • Network access to the intended JPS920 AIS server plus an available LLM connection.
  • JDE Basic Auth user with read access to F4211, F4201, F41021, F4311, F4101, and F0101.

Safety controls

  • The OpenAPI definition exposes GET operations only and fixes the builder-managed headers.
  • Status 900 is treated as inactive after the user correction.
  • Cross-branch donors must remain at or above the learned 1,000-unit floor.
  • The agent cannot claim to release or change JDE and requires explicit approval.

Demo flow

Session 1 — teach through ordinary feedback

User

Can you review today's backorders and tell me what we should tackle first?

User

We do not prioritize by quantity. Start with the earliest requested line that is still active.

User

Good. Make the status rule explicit: any line with last status 900 is inactive and stays out of the fulfillment queue.

User

For cross-branch recovery, do not recommend a donor if its indicative balance would fall below 1,000 units after the move. Show the arithmetic.

User

One more thing: anything that changes JDE needs my approval. Keep your recommendations read-only until then.

Session 2 — apply learned rules

User

Can you review today's backorders and tell me what we should tackle first? If the local branch cannot cover it, include the best cross-branch fallback and show the numbers.

User

Assuming those checks pass, should the team release it?

Expected outcomes

  • The agent connects without asking for environment, role, device, or credentials.
  • The earliest requested active line wins; status-900 lines stay out.
  • Ineligible donors are labeled with explicit post-transfer arithmetic.
  • Applied from your prior feedback lists relevant business rules without exposing memory internals.
  • The follow-up preserves the approval and authorized-execution boundary.
