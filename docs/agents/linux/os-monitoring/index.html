What it demonstrates

What is putting this Linux machine under pressure, and which applications explain it?

  • CPU and memory with measured assigned limits and explicit units.
  • osquery process and listener evidence, plus two application APIs and three background jobs.
  • Timestamped findings and actual coverage of up to 30 minutes of measurements.
  • Application roles, process IDs, health checks, work counters and human follow-up.

Prerequisites

  • An x86_64 Linux host with Podman, enforceable cgroup CPU/memory/pids controls, slirp4netns and a private route from Factory.
  • The monitoring service deployed with documented resource caps and private source firewall allowlist.
  • Factory 26.7 and configured OpenAI Compatible model AIW26-PAF-HOL6004-BOO6096.
  • Administrator-approved HTTP outbound access and private destinations permitted in Factory, or a trusted private HTTPS endpoint.

Safety controls

  • Six read-only tools; no SQL, shell, scenario-control or remediation tool.
  • Private source allowlist and firewall deny rule; no authentication or public listener is provisioned.
  • One CPU, 1536 MiB memory including swap, 128 pids, read-only root filesystem, no capabilities and bounded tmpfs.
  • Operator faults expire after 10–300 seconds; switching/resetting removes the previous fault.
  • Machine, filesystem and history coverage remain explicit; tool failures cannot establish health.

Import and configure

  1. Follow integrations/linux-os-monitoring/README.md to deploy the monitoring service. Infrastructure automation belongs in ~/work/infra/ansible.
  2. Check the instance outbound URL policy: the private HTTP endpoint needs administrator-approved ALLOW_INSECURE_HTTP_URLS=true and BLOCK_PRIVATE_OUTBOUND_URLS=false. Add Linux OS Monitoring as a Direct connection MCP source at http://monitor.example.invalid:8085/mcp and discover the six documented tools.
  3. Import linux-os-monitoring.paf and select the new local source on the MCP server node; review the six allowed tools. Environment-local source IDs are not portable.
  4. Select AIW26-PAF-HOL6004-BOO6096 on the Agent node. Configure that same OpenAI Compatible model name in every target instance; credentials/model definitions are not bundled.
  5. Disable Agent Memory and sharing between chat threads; exported archives do not carry these switches. Read the sticky notes left to right, then expand Agent description for the walkthrough and sample questions.
  6. Run the baseline prompt, then trigger one scenario with labctl as an operator, ask its matching question and reset. Review the draft before publishing.
