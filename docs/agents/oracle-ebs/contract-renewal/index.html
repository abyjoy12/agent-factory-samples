What it demonstrates

How can I renew a BPA using historical evidence and verify the new agreement in EBS?

  • Read the authorized source BPA and every current line price, then cite historical EBS PDF passages using scoped vector retrieval.
  • Show evidence gaps, proposed dates and all old/new prices before staging an immutable draft and validating its exact hash.
  • Request a recipient in the current chat and send the authoritative readable review email through native Send/Cancel confirmation.
  • Record the later user-entered code and reason, then submit only on a separate later request through Import Price Catalogs.
  • Check asynchronous import results and show the new Incomplete BPA for buyer verification in Oracle Forms.

Connection context

Two restricted sources: EBS-local PL/SQL renewal functions and ADB-S document MCP with scoped vector search. The native Email output tool uses the administrator-configured SMTP sender.

Agent Memory

Enable Agent Memory and cross-thread sharing separately after import for presentation preferences only. Always reread scope, prices, draft hashes, review and import status. Recipients must come from the current conversation; do not store addresses or reuse authorization from memory.

Prerequisites

  • PAF 26.7-compatible visual Agent Builder and model AIW26-PAF-HOL6004-BOO6096.
  • Installed EBS staging/API packages, identity scope and exactly seven AF_EBS_RENEWAL wrappers; never use APPS as the agent datasource.
  • Scoped document capture and vector embeddings on ADB-S, exposed through the three AF_EBS_DOC_MCP tools.
  • A working administrator-configured SMTP sender, a user-supplied recipient and access to Purchasing Purchase Order Summary in Oracle Forms.

Safety controls

  • The database identity maps to an active EBS user, responsibility, operating unit and source agreement. Dedicated accounts need separately scoped sources.
  • Writes use custom staging and Purchasing interfaces; no direct Purchasing base-table updates or final approval of the resulting agreement.
  • Initial scope: Approved, open, local USD goods BPAs, 1–100 active lines, uniform 0–10% uplift and at most 366 inclusive days starting today or later.
  • Draft hashes, recipient binding, review expiry, retry limits and idempotency are checked in the database; changed terms require a new draft and review.
  • The fixed code 6004 is for demonstration and is not authentication or proof of mailbox ownership. Successful-send and later-human-turn checks are agent instructions.
  • Email recipient must be explicitly supplied in this conversation for this draft. Missing address, failed/ambiguous send or stale review stops the action.
  • Show concise receipts; never print HTML, raw tool JSON or a second copy of the email. Native confirmation is the single email preview.
  • Historical PDFs cannot establish missing legal clauses or permission. Preserve evidence gaps; final agreement approval remains a buyer action.

Import and configure

  1. Install the EBS transaction and document retrieval setup from integrations/ebs-contract-renewal/README.md; keep runtime credentials and endpoints private.
  2. Import the generated ebs-contract-renewal.paf using the repository archive passphrase and leave it unpublished while reviewing.
  3. Bind __EBS_DATABASE_SOURCE_ID__ to the restricted transaction source and __DOCUMENT_MCP_SOURCE_ID__ to the scoped document MCP source. Verify seven renewal functions and three document tools.
  4. Replace __SOURCE_HEADER_ID__ and __SOURCE_BPA_NUMBER__ with the agreement authorized by that account. Prompt substitutions do not expand database scope.
  5. Select AIW26-PAF-HOL6004-BOO6096 and configure the SMTP sender privately. Leave the workflow recipient blank; the user supplies it in chat.
  6. Apply the per-user Agent Memory and sharing settings separately after import. Run read-only checks before explicitly staging or requesting email.
  7. Keep the demo in one saved conversation; approve only after a successful send in a later turn, submit separately and inspect the returned BPA in EBS.

Expected outcomes

  • A saved conversation containing cited evidence and gaps, reviewed proposal, immutable draft/hash, email outcome, later review and separate import receipt.
  • A verified new Incomplete BPA with matching validated prices, ready for buyer inspection rather than final EBS approval.
